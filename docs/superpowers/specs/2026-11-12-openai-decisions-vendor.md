## 1. Web docs
- Models: only gpt-6-luna. [FETCH] https://developers.openai.com/api/reference/resources/decisions ("Only `gpt-6-luna` is supported."); guide https://developers.openai.com/api/docs/guides/decisions ("Currently, only gpt-6-luna is supported"). [SRC] SDK docstring in decisions.py @v3.49.0 says same.
- Lifecycle [FETCH] https://developers.openai.com/api/docs/changelog : beta 2026-10-06 ("Released the Decisions API in beta with gpt-6-luna", "10x faster than the Responses API"); GA 2026-10-22 (shared-input caching, images in question instructions, input_json, 400 questions up from 200). GPT-Live integration 2026-10-15. Other sources (SEARCH) disagree on beta date (29 Sep); trust changelog.
- Pricing, gpt-6-luna, standard, <=272K input [FETCH] https://developers.openai.com/api/docs/pricing : input $0.10/1M, cached input $0.01/1M, output $0.50/1M, cache write 30m $0.125/1M (12h $0.25). >272K: $0.20 / $0.02 / $0.75 / $0.25 (30m) / $0.50 (12h). Pricing page does NOT mention Decisions. Guide page fetch said "uncached input costs $0.10 per 1M tokens" and "output tokens are not charged" (FETCH; CONFLICTS with the pricing page's $0.50 output; treat Decisions-specific output billing as unverified; verify by reading the guide verbatim). Regional processing +10%.
- Rate limits: none documented for Decisions or gpt-6-luna by name. [FETCH] https://developers.openai.com/api/docs/guides/rate-limits lists a "Luna" family (Build 5,000 RPM/2M TPM; Launch 10,000/10M; Grow 30,000/180M); unclear if it is gpt-6-luna. Guide says usage endpoint needs admin key with api.usage.read (SDK has types/admin/organization/usage_decisions_*).
- Images [FETCH guide+reference]: image_url = base64 data URL or public http(s) URL (max 1,073,741,824 chars); no file_id; detail low|high|auto(default)|original ("using the selected model's image profile" [SRC] shared/decision_question_input_image.py). NO count, pixel or byte limits documented; question images share "the request's image limits" with input images (limits never stated). Files, audio, item references unsupported. input_json only in user messages (input) ; question-instruction arrays may carry text/image/json parts.
- Refusal: per-question; [SRC] decision.py docstring: "Any question can return a refusal instead of an answer; other questions can still receive answers. A refusal has type 'refusal' and the question's name, or null if unnamed." [FETCH] "The model declined to answer this question." No reason field; when produced is undocumented.
- Errors/status codes: NOT documented on reference or guide (only 200 example). Changelog only has generic note (Sep 2): slow_down 429 and server_is_overloaded 503 [FETCH]. Assume standard OpenAI {error:{message,type,param,code}}; invalid question behaviour undocumented. Unverified.
- stream: not present. store, metadata, service_tier: not present. [FETCH reference]; [SRC] SDK create() has none of them (below).
- prompt_cache_key: string, max 64 (reference [FETCH]); SDK Optional[str]. prompt_cache_options: {mode:"implicit"|"explicit", ttl:"30m" only/default}; up to 4 breakpoints written per request; implicit = one automatic breakpoint at end of shared input; explicit = disables it, request with no marked breakpoints doesn't cache. [SRC] decisions.py docstring: "Supported for gpt-5.6 and later models ... considers up to the latest 80 breakpoints". Breakpoint = prompt_cache_breakpoint:{mode:"explicit"} on text/image parts of input; NOT supported in question instructions. Cacheable prefix must be >=1,024 tokens; question content not counted [FETCH guide]. usage cached_tokens/cache_write_tokens are included in input_tokens. safety_identifier: opaque, org-scoped, max 128 ([FETCH reference]; SDK docstring [SRC] "Opaque caller-provided end-user identifier, scoped by the verified org... never the authenticated user identity"). Guide fetch said safety_identifier not mentioned there.
- Predicate criteria: no yes/no-description field. Criterion lives only in natural-language `instructions` (string or parts array). Answer = probability 0..1 of true; no default threshold [FETCH guide]. => noul criteria {true,false} descriptions have no wire slot; fold them into instructions text (or choice with boolean values + per-choice `description`, which exists).

- Additional SDK surface: lib/decisions_tool_runner.py, types/live/decision_* (GPT-Live delegation), admin usage_decisions params/response. Not part of /v1/decisions wire.
